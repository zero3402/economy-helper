# ADR-0010 — 기상청 단기예보

> **한 줄 요약**: 기상청은 국내 오늘~3일 뒤만 맡는다. 키는 다시 인코딩하지 않고, 오늘 오전과 하루 최저·최고는 02시 발표로 채운다. 강수가 하늘 상태보다 우선이다.

| 상태 | 범위 |
|---|---|
| 채택 | `weather/adapter/out/kma/**` · `weather/domain/**` |

## 맥락

기상청 단기예보(공공데이터포털)는 국내 날씨의 1순위다.

**장점**
- 일별과 시간별을 한 출처가 같이 준다. 그래서 국내에서는 「한 블록의 강수 값은 한 예보에서」가 완전히 지켜진다.
- 새 키 없이 주식 2순위와 같은 `DATA_API_KEY`를 쓴다.

**단점**
- 발표 시각 + 1시간 이후 데이터만 준다.
- 하루 최저·최고 기온은 이른 발표에만 들어 있다.
- 날씨 표현 어휘가 적다.

## 결정

### 호출

1. **키를 다시 인코딩하지 않는다**(`KmaRequest` · `DataGoRequest`가 받은 그대로 보낸다). 키가 없으면 아예 부르지 않는다.
2. **에러 응답을 따로 읽는다.** 키가 틀리면 `{"OpenAPI_ServiceResponse":{"cmmMsgHeader":…}}`가 HTTP 200으로 온다.
3. 조회 한 번에 호출 한 번이다(오전 메우기 보충 호출만 더해진다). 서비스키가 URL에 들어가므로, 실패할 때는 키를 지운 예외로 감싼다.

### 국내 판정

4. **「국내인가」는 격자와 시간대(`Asia/Seoul`)가 함께 정한다.** 나라 이름으로는 판단할 수 없다(알람은 지오코딩을 거치지 않아 나라 정보가 없다).

### 쓰는 기간

5. **단기예보만 쓴다 — 오늘부터 3일 뒤까지.** 오늘은 발표 시각 이후만, 3일 뒤는 3시간 간격 8칸을 쓰고, 4일 뒤의 00시 한 칸은 버린다.
6. **중기예보(4일 뒤 이후)는 쓰지 않는다.** 붙였다가 되돌렸다(아래 근거).
7. **물어본 날 중 하루라도 비면 예외를 던진다.** 이 출처만 계약보다 엄격하다. 일부만 성공한 답을 내면 예비 출처로 넘어가지 않고 10분 캐시에 남는다.

### 오늘의 오전과 하루 최저·최고

8. **반나절 둘 중 하나라도 없으면 02시 발표로 채운다.**
   - 시각별로 겹쳐 합치고, 같은 시각은 최신 발표가 이긴다.
   - 채우는 조건은 「반나절 둘이 다 있는가」다(「`TMN`이 없는가」가 아니다).
   - 그래도 못 채우면 그 날을 버린다(오늘이라도). 예비 출처가 두 줄을 온전히 준다.
9. **오늘의 하루 최저·최고도 02시 발표에서 가져온다**(빠진 것만).
   - 부가 정보라 실패는 삼키고, 그때는 최저·최고 둘 다 시간별 값으로 계산한다.
   - 오늘을 묻지 않는 조회에서는 부르지 않는다.

### 날씨 표현 (`KmaSky`)

10. 코드 → 표현

    | 코드 | 표현 |
    |---|---|
    | `PTY=0` + `SKY=1` / `3` / `4` | `맑음` / `구름 많음` / `흐림` |
    | `PTY=1` / `4` | `비` / `소나기` |
    | `PTY=3` / `2` | `눈` / `진눈깨비` |

    - **강수(PTY)가 하늘 상태(SKY)보다 우선이다.**
    - `구름 많음`(🌥️)을 새로 둔다.
    - `PCP`의 `강수없음`은 `null`이 아니라 `0`이다(「안 온다」고 말할 수 있어야 한다).

## 결과

- 기상청이 맡은 날에는 이슬비·뇌우·안개가 나오지 않는다. 기상청이 그런 표현을 주지 않는다.
- `providesPrecipitationHours()`가 참이라 국내에서는 보충 호출이 없고, 출처 줄도 한 줄이다.

## 근거 (실측)

| 항목 | 관찰 |
|---|---|
| **키** (2026-08-26) | `DATA_API_KEY`로 `resultCode=00`. 발급 키에 `%`가 들어 있어(길이 96) 한 번 더 인코딩하면 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`가 오는데, 이걸 「활용신청이 안 됐다」로 잘못 읽은 적이 있다 |
| **격자** (2026-08-26) | 격자 안이지만 국외: 후쿠오카 `(123,42)` · 쓰시마 `(103,55)` · 평양 `(39,158)` · 블라디보스토크 `(135,250)` · 선양 `(2,219)`. 격자 안이고 국내: 울릉도 `(127,127)` · 독도 `(144,123)` · 마라도 `(48,29)` · 백령도 `(20,135)` |
| **날짜별 데이터** (2026-08-26 05시 발표) | 오늘 06~23시 18칸, 1·2일 뒤 24칸, 3일 뒤 3시간 간격 8칸, 4일 뒤 00시 한 칸 |
| **중기예보를 되돌린 이유** | 도 단위 광역이고 시각을 주지 않는다. 지역코드 체계가 둘(육상 광역 10개 ↔ 기온 지점)이라 가장 가까운 대표 지점으로 권역을 골랐는데, 대표 지점 26개 · 표본 42곳에서 완도가 제주 권역으로, 남해 · 옥천 · 가평이 이웃 권역으로 갔다(30개로 늘려도 5곳이 틀렸다) |
| **오전 공백** | 문제가 생기는 시간대는 11:10 ~ 23:09 KST — 오늘이 「오후」 한 줄로만 나갔다(신고됨). 02시 발표에 오늘 21칸(03~23시, 오전 9칸)이 남아 있고 오후에도 조회된다(14:29 · 15:27 확인) |
| **하루 최저·최고** | 02시 발표에는 `TMN 24.0` · `TMX 32.0`, 05 · 11시 발표에는 `TMN`이 없고, 14시 발표에는 둘 다 없다 |
| **`PCP`** | `'0'` · `'1'` · `'2'` · `'강수없음'`. 문서에는 `"1.0mm 미만"` · `"30.0~50.0mm"`도 있다 |
| **일곱 지점** | 국내 여섯 곳 모두 오늘~3일 뒤가 반나절 둘씩 채워졌고, 파리는 맡지 않았다 |
