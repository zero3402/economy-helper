# ADR-0003 — 국내 종목·ETF 찾기

> **한 줄 요약**: 이름 → 종목코드는 KIS 종목 마스터 파일로 찾는다. LLM은 이름을 다듬기만 하고, 코드는 색인이 확정한다. 2순위 시세는 공공데이터포털.

| 상태 | 범위 |
|---|---|
| 채택 | `stock/**` |

## 맥락

`/stock`은 약칭과 자연어(`삼전`, `타임나스닥100`, `제피`)를 받는다. 그런데 출처마다 할 수 있는 일이 다르다.

| 출처 | 이름으로 검색 | 비고 |
|---|---|---|
| KIS | 안 됨 (코드 → 이름만) | |
| 공공데이터포털 주식시세정보 | 됨 | **주식만** 준다 |
| 공공데이터포털 증권상품시세정보 | 됨 | 국내 ETF. 별도 API이고 활용신청도 따로다 |

## 결정

1. **이름 → 종목코드 색인은 KIS 종목 마스터 파일로 만든다**(`kospi_code.mst.zip` · `kosdaq_code.mst.zip`, `KisMasterClient` → `StockListings`).
   - 키가 필요 없다.
   - Redis 캐시(`kr-listings`) 6시간 + 프로세스 안 사본 6시간.
   - **6자리 단축코드만** 남긴다(KIS 국내 시세가 받는 형식).
2. **색인에서 찾는 규칙**
   - 정규화한 이름이 정확히 같은 종목이 있으면 그것.
   - 없으면 검색어를 숫자·영문·한글 토큰으로 쪼개, **토큰을 전부 포함하는** 종목 중 **시가총액 1위**.
   - 한 글자처럼 너무 짧은 부분 일치는 쓰지 않는다.
   - 지수 이름(`digest.indices`)은 부분 일치보다 먼저 정확히 맞춘다.
3. **LLM(`StockResolver`)은 상장명을 소리로 맞춰 내고, 코드는 색인이 확정한다.**
   - 국내 ETF: 「코드는 확실할 때만, 이름은 KRX 상장명으로 — 브랜드는 영문 그대로(타임 → TIME)」.
   - 한글로 쓴 미국 티커(`제피 → JEPI`)도 LLM이 소리로 맞춘다. 대응표를 따로 두지 않는다.
4. **코드와 이름이 서로 다른 종목을 가리키면 이름을 믿는다**(`StockListings.sameListing`).
   - 단, 이름이 **정확히 일치하는** 종목이 있을 때만이다. (`삼성전자우`는 `삼성전자`의 토큰을 다 포함하므로 부분 일치로는 구분이 안 된다.)
   - 이름으로 못 찾으면 코드를 쓴다(`네이버` → `NAVER`).
5. **화면 이름은 코드가 정한다**(`StockService.displayName`). 한글 이름이 없으면 티커로 적는다.
6. **2순위는 공공데이터포털(전일 종가)이다.**
   - 주식은 `StockPriceApi`, ETF는 `EtfPriceApi`(`getETFPriceInfo`).
   - 코드로 조회할 때는 응답의 `srtnCd`가 **정확히 같은 행만** 받는다.
   - 이름 검색은 API마다 최신 기준일을 따로 고르고, 주식·ETF 후보를 합쳐 시가총액 1위를 고른다.
   - **브레이커는 주식(`dataGo`)과 ETF(`dataGoEtf`)를 나눈다.**
7. **LLM이 지수로 잘못 분류해도** 국내 이름 검색으로 한 번 더 찾는다. 마스터 파일 갱신이 실패하면 **이전 색인을 그대로 쓴다.**
8. 색인이 ETF·ETN이라고 알려 주면 목표주가를 묻지 않는다(배당은 묻는다). ETF의 `invest-opinion`은 0행이다.

## 결과

- 이름으로 찾은 국내 종목에도 코드가 생기므로 1순위 실시간 시세·전망·차트가 붙는다.
- LLM이 없으면 `타임나스닥100`은 못 찾는다(`타임` ≠ `time`).
- `kr-listings` 캐시를 비워도 프로세스 안 사본은 수명이 다할 때까지 남는다.
- 이름 검색은 호출이 두 번이다(주식·ETF, 하루 1만 회 한도, 1시간 캐시).

## 근거 (실측)

| 항목 | 관찰 |
|---|---|
| **공공데이터포털 이름 검색** (2026-08-28) | 주식시세정보에 `likeItmsNm=KODEX` / `나스닥100` / `TIME` → 0건(`삼성전자`는 2건). 증권상품시세정보는 활용신청 전 403 `SERVICE_KEY_IS_NOT_REGISTERED_ERROR`(같은 `DATA_API_KEY`, 2026-08-28 승인) |
| **마스터 파일 형식** | 두 파일 220KB에 ETF 1,164건. **공식 파이썬 예제의 꼬리 길이(228/222)와 한 글자 다르다** — KOSPI 227 · KOSDAQ 221. `꼬리[0:2]`가 그룹코드(`EF`가 ETF), `꼬리[-15:-6]`이 시가총액(억 원). 영숫자 6자리 `0019K0`도 KIS가 받는다. Redis 값이 292KB·4천 행이라 조회마다 풀면 `/stock` 한 번에 네 번씩 풀었다 → 프로세스 안 사본을 둔다 |
| **LLM** (`gemini-flash-lite-latest`) | 2026-08-26 한글 미국 티커 9개, 2026-08-28 국내 ETF 상장명 10개를 모두 맞혔다. 「name은 사용자가 부른 이름으로」를 프롬프트에 넣자 `삼전`과 `나스닥`을 못 찾게 됐다 — 문단 하나가 다른 판단까지 흔든다 |
| **`getETFPriceInfo`** | `srtnCd=426030`을 줘도 1,164건 전부가 온다(`srtnCd`가 무시된다) → `likeSrtnCd`로 묻고 응답을 거른다. 필드 이름이 주식과 같고, `fltRt`가 `-.14` 같은 꼴로 온다 |
| **존재하는 틀린 코드** | LLM이 KODEX의 코드에 TIME의 이름을 주면, KIS가 정상 응답해 엉뚱한 ETF가 나갔다 → 결정 4 |
| **2026-10-03 수정** | 공공데이터포털이 코드 부분 일치로 다른 종목을 주던 것(`5930`)과, 주식·ETF 기준일을 섞어 「삼성」이 ETF로 나가던 것을 고쳤다 |
