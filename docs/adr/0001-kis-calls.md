# ADR-0001 — KIS 호출 규칙

> **한 줄 요약**: KIS는 호출 사이 1초를 지키고, 토큰은 하나만 쓰며, 에러는 `msg_cd`로 구분한다. 응답의 `0`은 값이 아닐 수 있다.

| 상태 | 범위 |
|---|---|
| 채택 | `infrastructure/kis/**` · `stock/**` · `fx/**` |

## 맥락

한국투자증권(KIS) Open API는 환율·국내 시세·미국 시세의 1순위 출처다. 모의투자 계정을 쓰고, 세 기능이 **앱키·토큰·호출 간격을 모두 공유**한다.

KIS는 다른 출처와 실패하는 방식이 다르다.

- 한도가 「초당 N건」이 아니라 **「호출 사이 간격」**이다.
- 토큰이 무효면 401이 아니라 **500**을 준다.
- 응답의 `0`이 실제 값이 아닐 때가 있다.

## 결정

### 1. 호출 간격을 직접 지킨다

`KisThrottle`이 호출 시작 사이에 `market.kis.min-interval`(기본 1초)을 둔다. 토큰 발급도 이 간격을 지킨다.
리미터(`kis`)는 계정 단위로 따로 두지만, 간격 자체는 리미터로 표현하지 않는다.

### 2. 토큰은 Redis(`kis:token`)에 하나만 둔다

- 프로세스 안에서는 `ReentrantLock`으로 한 번에 하나만 발급한다.
- 인스턴스 사이에서는 Redis 락(`kis:token:issuing`)으로 막고, 락은 내 값일 때만 지운다.
- Redis가 죽으면 프로세스 안의 사본을 쓴다.

### 3. 실패는 `msg_cd`로 구분한다

`KisHeaders`·`KisResponse`가 처리한다. HTTP 200인데 본문이 `rt_cd=1`인 경우도 같은 길로 간다.

| `msg_cd` | 뜻 | 할 일 |
|---|---|---|
| `EGW00121` | 토큰 무효 | **버린다**(`KisTokenStore.invalidate`). 발급 6시간 뒤에 다시 받는다 |
| `EGW00304` | 앱시크릿이 틀림 | 사람이 키를 고친다. 토큰은 건드리지 않는다 |
| `EGW00201` | 초당 호출 수 초과 | **한 번만 다시 부른다**(`KisCall`, 호출 간격을 다시 지킨다). 유일하게 일시적인 실패다 |
| `EGW00105` | 앱시크릿을 잘못 보냄 (발급 403) | 키 끝의 줄바꿈부터 의심한다. 생성자가 `trim`한다 |

### 4. 다른 5xx는 재시도하지 않는다

KIS에서 500은 대개 영구 실패다.

### 5. 조회 키는 설정 파일에 둔다

| 대상 | 키 | 예 |
|---|---|---|
| 국내 지수 | 업종코드 | 코스피 `0001`, 코스닥 `1001` |
| 미국 지수 | KIS 심볼 | `COMP`, `.DJI` |
| 미국 종목 | 거래소 코드 | |

지수 표(`market.kis.us-indices`)와 브리핑 목록(`digest.us-symbols`)은 따로 둔다.

### 6. 미국 종목의 거래소는 NAS → NYS → AMS 순으로 찾는다

- 찾은 거래소는 30일 기억한다(`KisExchangeCache`).
- 셋 다 비면 장애가 아니라 `Unsupported`를 던진다(브레이커를 열지 않는다).
- 다른 방법이 다 실패하면, 원문이 영문 1~5자일 때 대문자로 한 번 더 묻는다. 이걸 먼저 하지 않는 이유: `KO`·`SO` 같은 티커가 국내 이름 검색을 가로챈다.
- **클래스 주식은 KIS 표기 `/`로 묻는다** — `BRK.B` · `BRK-B` → `BRK/B`(`KisStockApi.kisSymbol`). 원문의 구분자는 정규화 전에 읽는다(지워지면 `BRKB`라는 없는 티커가 된다).

### 7. `0`은 값이 아니다

- 지수 `0`, 날짜가 빈 일봉은 버리고 다음 출처로 넘어간다.
- 국내 지수 이름(`종합`·`KOSDAQ`)은 화면에 쓰지 않고 설정의 이름을 쓴다.
- 등락률 필드 이름이 지수(`bstp_nmix_prdy_ctrt`)와 종목이 다르다.
- 미국 종목은 달러 등락률 필드가 없어서 `last`·`base`로 계산한다.

### 8. 장이 닫힌 날은 (종가)다

마지막 일봉 날짜가 그 시장의 오늘이 아니면 `realtime=false`로 두고, 시각 대신 그 날짜를 보여 준다.

## 결과

- 브리핑은 KIS를 연달아 부르므로 마지막 호출은 몇 초를 기다린다. 원래 치러야 했던 비용이다.
- 토큰이 무효가 되면 최대 6시간 동안 KIS 없이 2순위 출처로 돈다.
- 미국 목표가·실적발표일은 KIS로 대신할 수 없다. 한투에 해외 목표주가가 없다.
- 투자의견은 화면에서 뺐다. 다시 넣는다면 `invt_opnn_cls_code`를 등급으로 쓰지 않는다(「매도」가 조용히 「중립」이 된다).
- 실전 계정으로 옮겨 간격이 1초보다 줄면 재시도 계산을 다시 본다.

## 근거 (실측)

| 항목 | 날짜 | 관찰 |
|---|---|---|
| **호출 간격** | 2026-08-19, 모의 | 같은 요청을 커넥션을 재사용하며 0.2초 간격으로 보내면 두 번째가 HTTP 500 「초당 거래건수 초과」. 1초 간격은 셋 다 200. 매번 새 커넥션이면 0.05초도 200. 앱은 커넥션 풀을 쓰므로 항상 「재사용」이다 — `curl`로는 재현이 안 된다. 고정 윈도 리미터(`1/1s`)는 경계에서 허용을 120ms 간격으로 두 번 냈다 |
| **무효 토큰** | 2026-08-19 | `/stock 유아이패스`·`오라클`·`스노우플레이크`가 결과 없음이었고, 로그의 `InternalServerError`를 「NYS가 죽었다」로 잘못 진단했다. 같은 요청을 유효한 토큰으로 보내면 12/12 성공(`PATH` 15.52 · `ORCL` 141.61 · `SNOW` 323.00). 응답 본문: `{"rt_cd":"1","msg1":"유효하지 않은 token 입니다.","msg_cd":"EGW00121"}`. 앱키당 유효 토큰은 하나이고, 1분 안에 다시 발급하면 앞 토큰이 죽는다 — 검증 중 앱을 네 번 재시작하며 토큰 캐시를 버린 것이 원인이었다 |
| **6시간 창** | 2026-08-19 | 6시간 안에 다시 발급하면 같은 죽은 토큰이 온다(응답의 만료 시각이 요청 시각보다 20분 일렀다) |
| **발급 성질** | | 유효 24시간(`expires_in=86400`), 1분에 한 번, 발급할 때마다 계정주에게 알림톡. 만료 시각은 `expires_in`이 아니라 `access_token_token_expired`(시간대 표시 없는 KST)로 읽는다 |
| **`EGW00304`** | 2026-08-20 | 잘못된 앱시크릿도 500. 거절 한 번에 2.2~3.5초(커넥션 재사용 3회) |
| **`EGW00201`** | 2026-08-20, 실물 감사 2026-09-29 | 1초 간격을 지켜도 모의 서버가 가끔 준다(`PATH` NAS→NYS, 삼성전자 배당일정). 한 번에 포기하면 `/s 유아이패스`가 결과 없음이 되고, 전망이 배당 줄 없이 12시간 캐시에 남았다 |

| **클래스 주식** | 2026-10-03 | 키 없이 받는 공개 KIS 해외 마스터(`nysmst.cod.zip`)에 `BRK/A`·`BRK/B`(버크셔 해서웨이 A·B)·`ABR/D`·`AGM/A`처럼 `/`로 적혀 있다. FMP로는 확인하지 않았다(2순위에는 점 표기 그대로 묻는다) |
