# 새 외부 출처 붙이기

이 저장소의 사고는 거의 전부 **「출처가 어떻게 응답하는지」를 추측한 데서** 났다.

진행 방법:

1. 붙이기 전에 아래 항목을 **실제로 호출해서** 확인한다.
2. 확인한 내용은 ADR(`docs/adr/`, 쓰는 법은 `docs/adr/README.md`)에 **날짜·파라미터와 함께** 남긴다.
3. 계속 지켜야 할 규칙이면 해당 패키지 `AGENTS.md`에 `→ ADR-00NN`을 단 한 줄로 올린다.

각 항목의 자세한 설명은 괄호 속 문서에 있다. 여기에 다시 쓰지 않는다.

## 호출하기 전에

- [ ] 키, 무료 한도, 초당·분당·일일 한도를 실제로 잰다. 키 이름은 `backend/.env.example`에 「없으면 무엇이 안 되는지」와 함께 넣는다.
- [ ] 비슷한 출처에서 겪은 함정을 읽는다 — KIS(ADR-0001), FMP 허용목록(ADR-0004), 공공데이터포털 키 이중 인코딩(ADR-0010).

## 응답을 읽을 때

- [ ] **에러가 어떤 모양으로 오는가** — HTTP 200에 다른 JSON(공공데이터포털), 500인데 영구 실패(KIS), `rt_cd=0`(성공)인데 빈 값. 상태 코드만 믿지 않는다.
- [ ] **`0` · `""` · `"0"` · `null`이 실제 값인가, 「모름」인가** — 모름이면 그 줄을 적지 않는다(루트 `AGENTS.md` 원칙).
- [ ] **배열 이름·필드 이름은 실제 응답에서 그대로 베낀다** — `@JsonIgnoreProperties` 때문에 틀려도 에러 없이 빈 목록이 된다.
- [ ] **날짜는 STRICT로 읽는다**(`docs/design.md` 4.8). 한 행 안에서도 필드마다 형식이 다를 수 있다.
- [ ] **「오늘」은 그 시장·그 지역의 달력**으로 자른다.

## 보호 장치

- [ ] 리미터는 **앱키 단위**, 브레이커는 **출처 단위**, 재시도는 **예비 출처가 없는 곳만**(`docs/design.md` 4.4). 영구 실패(없는 심볼·402)가 브레이커를 열지 않게 한다.
- [ ] 캐시 TTL과 판 번호(`docs/design.md` 4.2). 빈 답은 `null`이 아니라 빈 값 객체로 담는다(스프링 캐시가 `null`을 거절한다).
- [ ] 이중화 순서에 넣는다면 포트 하나 + 순서 목록 하나(`docs/design.md` 4.1). 화면에 출처와 기준 시각이 나오게 한다(4.7).
- [ ] URL 끝 슬래시 — 308 리다이렉트를 RestClient가 따라가지 않는다(ADR-0014).

## 테스트

- [ ] 실제 응답을 WireMock 스텁으로 만든다(CI는 시크릿 없이 돈다). 「모름」 모양(`0` · 빈 배열 · 다른 에러 JSON)도 하나씩 스텁한다.
- [ ] `cd backend && ./gradlew test`가 통과해야 다음으로 넘어간다. 마지막에 `/real-audit`로 실제 응답을 확인한다.
